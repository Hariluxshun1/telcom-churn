# Final Model Selection and Handover — Member 3

**Source notebook:** `notebooks/07_model_comparison.ipynb`  
**Decision:** Balanced Logistic Regression, operating threshold **0.60**.

## Decision rationale

The four-algorithm standardized CV evaluation narrowed the choice to balanced Logistic Regression and XGBoost. A second-stage nested **threshold** comparison found mean F1 of **0.6354** for Logistic Regression and **0.6355** for XGBoost. These values are practically identical. Logistic Regression was chosen because it is simpler to interpret and supports the project's second objective: explaining customer churn-risk patterns.

This is a pragmatic simplicity/interpretability choice, **not** proof that Logistic Regression outperforms XGBoost.

## Selection procedure

1. Use `X_train_raw.csv` and `y_train.csv` from the shared preprocessing split, not the held-out test set.
2. Use the balanced Logistic Regression pipeline with its preprocessing inside CV.
3. Compare finalist models using outer five-fold and inner three-fold threshold selection as documented in Notebook 7.
4. Generate training-only out-of-fold probabilities for the chosen Logistic Regression configuration.
5. Sweep thresholds **0.30–0.70** in steps of 0.05; **0.60** maximized the exploratory pooled OOF F1 (**0.6370**).
6. Fit the frozen pipeline once on all **5,634** training records, then save the model and threshold metadata before the final test evaluation.

The exploratory threshold sweep is not a separate validation estimate. The nested-threshold F1 (**0.6354**) is more informative, although earlier configuration selection still limits independence.
